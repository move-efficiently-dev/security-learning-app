# ウェブサイト要件定義書（ドラフト v0.1）

- サイト名：「仕事とITの研究所」ウェブサイト
- 作成日：2026年11月21日
- 位置づけ：セキュリティ教材の公開・周知を担う公式サイト。学習アプリ（別途要件定義）と対になる「表側」の媒体。
- 本書はドラフトであり、未決事項は第9章に集約する。

## 1. 目的と背景（業務要件）

### 1.1 背景
- 中小企業の情報システム部門・情報セキュリティ担当は、ISMS（ISO/IEC 27001）やIPAガイドラインの求める従業員教育を実施する必要がある一方、教材の作成やメンテナンスに時間を割けない。
- 本事業は、一定のクオリティを保ったセキュリティ教材をウェブサイトと学習アプリで提供し、企業の教育実施を支援することで、セキュリティ分野に貢献する。

### 1.2 サイトの目的
1. 教材（動画・解説記事・確認問題・チェックリスト）を公開し、誰でも学べる状態にする（周知・啓発）。
2. 教育サービスの内容と価値を伝え、学習アプリの利用登録・支援サービスへの問い合わせにつなげる（集客・導線）。
3. 教材のテーマとISMS管理策・IPAガイドライン項目との対応を示し、企業の教育計画に組み込みやすくする（信頼性）。

## 2. 対象ユーザー
- 中小企業の情報システム担当者・情報セキュリティ担当者（教材を探している人）
- 経営者・教育責任者（教育サービスの導入を検討する人）
- 一般の従業員（公開教材で学ぶ人）

## 3. 公式要件・ガイドからの根拠（サイトに関わるもの）

| 根拠 | 要点 | サイトへの要求 |
|---|---|---|
| JIS Q 27001 附属書A 6.3 | 教育・訓練に加え、方針・手順の「定期的な更新情報」を要員へ届けること | 教材・方針関連情報の継続的な公開と更新 |
| JIS Q 27002 6.3 手引⑤ | 伝達チャネルはウェブサイト、ニュースレター、eラーニング等の複数形式を用いる | 動画・記事・問題集など複数形式で同一テーマを提供 |
| JIS Q 27001 箇条7.3 | 要員は自社の方針、自らの貢献、違反時の影響を認識していること | 方針や責任の考え方を扱う解説コンテンツを用意 |
| IPAガイドライン 1-11 | 「情報セキュリティ教育サービス」は知識・スキルの習得支援と、対策の解説・周知支援の両面 | サイトは主に「解説・周知支援」を担い、アプリが「習得支援（受講・記録）」を担う役割分担 |
| IPAガイドライン 1-2 | 情報セキュリティ6か条が基本対策の入口 | 入門テーマの分類軸として6か条と対応づける |
| IPA ポイント学習 | 1テーマ短時間完結＋確認テストが標準形。分類軸は対象者×診断項目 | テーマ分類と教材単位の設計に採用 |
| IPA 10大脅威 | 脅威テーマは毎年入れ替わる | 年次でテーマ・教材を見直す運用を前提にする |

## 4. 機能要件

### 4.1 ページ構成（現行サイトを基礎とする）
- トップ：サイトの目的、特集テーマ、教材への入口、アプリ・有料記事・支援サービスへの導線
- 動画一覧：YouTube Shorts教材へのリンクとテーマ別整理
- 教材・記事一覧：note基礎シリーズ等の解説記事へのリンク
- 素材集：テーマ別の確認問題・チェックリスト（印刷対応）
- 有料記事：note有料記事の紹介と購入導線
- セキュリティニュース：公的機関等の最新情報を集約した一覧（4.5。検索流入の入口）
- 支援・問い合わせ：サービス紹介と問い合わせ導線

### 4.2 教材の分類・表示
- テーマ分類は複合軸とする：「基本対策（IPA 6か条対応）」「脅威・場面別（メール、テレワーク、内部不正等）」「対象者別（経営者／全従業員／新入社員／管理者・情シス）」。
- 対象者別の見せ方：経営者向けはリスクとコストの軸（事故時の損失額と対策コストの比較）で示し、従業員向けは日常の行動に直結する内容とする（アプリ要件定義書2節の「立場ごとの関心と見せ方」と共通）。
- 各テーマに、対応するISMS管理策（附属書A）とIPAガイドライン項目を明示する。
- 大きく表示する画像は、そのページ・記事の内容が一目で分かるアイキャッチとする（現行運用を要件化）。

### 4.3 更新管理
- 教材・記事の追加、差し替え、公開日・更新日の管理ができること。
- 教材には版（バージョン）の考え方を持たせ、改訂履歴を追えること（アプリ側の教材版管理と整合させる）。

### 4.4 計測
- アクセス解析により、テーマ別の閲覧状況を把握し、教材の改善・追加の判断に使うこと。

### 4.5 情報アグリゲーションと検索流入（2026-11-21 追加）
- サイトに「セキュリティニュース」セクションを設け、公的機関等の最新情報（注意喚起・脆弱性情報等）を集約して公開する。情報をまとめて見られる入口とすることが目的で、検索エンジン経由の流入（Google検索の上位表示）も狙う。
- 情報源と収集方法は、アプリ要件定義書4.9の収集設計（公式フィードの定期取得）と共通とする。表示は「見出し＋発表日時＋自前の3行程度の要約＋出典リンク」とし、本文の転載はしない。要約は出典本文のコピーではなく自前で作成する（著作権への配慮と、検索評価上の独自性の確保を兼ねる）。
- 分類はアプリ側と共通の3軸（情報の種別／脅威・手口／対象製品・機器）とし、カテゴリ別の一覧ページを用意する。脆弱性情報は製品名・CVE番号など具体的な検索語に対応しやすい。
- 表示範囲：サイトの一覧は最新分のみとする（目安は直近30日分または最新50件程度。最終値は実装時に確定する）。ただし個別情報のページとカテゴリ分類は蓄積として残し、検索流入の資産とする。過去分を含む全件の保持・検索・自社向けの抽出はアプリ側の役割とする。
- 各情報から関連する教材・記事・動画へ内部リンクを張り、流入を教材とアプリの案内へつなげる。
- SEOの基本方針：速報性（収集から公開までの速さ）、自前要約による独自性、カテゴリの網羅、内部リンクの整備を基本とし、転載中心の構成にはしない。
- 有料側の付帯機能（自動収集、カテゴリ分け、保存、URLの最新化）はアプリ側の役割とし、サイト側は掲載と出典への遷移に徹する（アプリ要件定義書4.9）。

### 4.6 広告枠（上位表示の掲載依頼への対応）
- セキュリティ関連サイト・ニュースサイト等から上位表示の掲載依頼があった場合に対応できるよう、広告枠の仕様を用意する。
- 掲載枠は通常の並び順（編集上の並び）と分けて管理する（位置、期間、表示ラベルを設定可能にする）。
- 広告である旨の表示（「PR」「広告」等）を必須とする（景品表示法のステルスマーケティング規制への対応）。
- 有料掲載のリンクには rel="sponsored" を付ける（検索エンジンの有料リンクポリシーへの対応）。
- 料金体系と掲載条件は未決事項（9節）とし、依頼が発生した段階で確定する。

## 5. コンテンツ要件（品質基準）
- 用語は公式ドキュメント・規格（JIS Q 27000／27001、IPAガイドライン等）の体系的な用語を使う。独自の造語は使わない。
- 教材は「1テーマ短時間で完結＋末尾に確認問題」の単位を基本とする。
- 素材（音楽・画像・フォント）は採用前に利用条件を確認する。参考画像は参考のみとし、そのまま使わない。
- フォントはGoogle Fonts「Noto Sans JP」（読みやすさのためゴシック統一）。デザイン規則は現行の確定事項（白基調、ネイビー#14213Dはボタン専用、ゴールド#FCA311は小アクセント専用、罫線1px統一、余白スケール8の倍数、3幅レスポンシブ）を維持する。

## 6. 非機能要件
- 対応端末：スマートフォン、タブレット、PCの3幅で読みやすく表示されること。
- 表示性能：画像は内容が伝わる範囲で軽量化し、モバイル回線でも実用的な速さで表示されること。
- 検索・共有：検索エンジンに正しく拾われる基本構造（タイトル、説明文、OGP）を備えること。
- セキュリティ：問い合わせ等で個人情報を扱う場合は、収集項目を最小限にし、取扱いを明示すること。
- 可用性：無料ホスティングの範囲で安定公開し、障害時は代替公開手段を検討できること。

## 7. 開発から運用保守・改善までの流れ

### 7.1 開発フェーズ
1. 要件定義（本書）→ 2. ワイヤーフレームでラフ確認 → 3. デザイン確定 → 4. 本編構築 → 5. 内容・リンク・表示の検証 → 6. 公開
（現行サイトはこの流れで構築・改修済み。今後の改修も同じ手順を踏む。）

### 7.2 運用保守（定常）
- 教材の追加・差し替え：動画・記事の公開に合わせて随時。
- 内容の定期見直し：IPA「情報セキュリティ10大脅威」の年次更新、および規格・ガイドラインの改定に合わせてテーマと教材を見直す。
- リンク切れ・表示崩れの点検：月1回を目安。
- アクセス解析の確認：月1回、テーマ別の閲覧傾向を記録する。

### 7.3 改善
- 閲覧の多いテーマは教材を厚くし、閲覧の少ないテーマはタイトル・アイキャッチ・導線を見直す。
- アプリ側の正答率データ（弱点テーマ）を、サイトの特集・解説の充実に還元する。
- 改善内容は版として記録し、いつ・何を・なぜ変えたかを残す。

## 8. 体制と役割
- 事業者（梅原基樹）：内容の最終確認、公開判断、問い合わせ対応。
- Muse：原稿・教材の作成補助、構築・更新作業、解析と改善案の提示。
- 外部AI（ChatGPT／Gemini等）：執筆・画像生成の下書き（役割分担は現行運用どおり）。

## 9. 未決事項・前提
- 公開ホスティング先の確定（無料枠の候補：Cloudflare Pages／Netlify等）と独自ドメインの要否。
- 問い合わせフォームの実装方法（外部フォームサービスの利用可否）。
- アクセス解析ツールの選定。
- サイトとアプリの連携範囲（アプリの教材ページからサイトの解説へ飛ばす等）は、アプリ要件定義と合わせて確定する。
- 広告枠（4.6）の料金体系と掲載条件。
